# 手机开发商 · Mobile Manufacturer

把《手机开发商设计方案》（GDD）里的核心系统做成一个**能真正玩的浏览器原型**：从年代科技树起步，亲手设计手机（2D 六视图 + 3D 模型同源联动），排产、定价、进入全球市场，和九家 AI 竞争对手抢份额。

纯前端，无构建步骤，原生 ES Module + three.js（已本地化到 `vendor/`）。

## 运行

```bash
npm start            # 启动本地服务器 http://127.0.0.1:8124
```

或任意静态服务器指向本目录（必须用 http 协议，ES Module 不支持 file://）。

```bash
python3 -m http.server 8124
```

## 玩法主线

1. **选年代开局**：1980 / 1990 / 2000 / 2010 / 2020 / 2035，起步公司掌握的是三四年前的成熟技术（`ERAS.lag`），留出一条可以追赶的研发队列。
2. **设计手机**：机身长宽厚、边框、屏幕、处理器、内存、存储、电池、影像、材质、装饰件。左侧调参，中间 2D 六视图与 3D 模型实时同步，右侧给出外观评分、BOM 成本、内部空间占用与装配检查（空间不足 / 摄像头凸起 / 折叠未成熟都会拦下量产）。
3. **量产与排产**：委托代工或自建工厂，设定月产量与质量投入；产能、现金、良率与**元器件库存**共同决定实际产出。
4. **供应链采购**：六大类元器件各有交期，先下单再生产；库存不足时按 **+16% 现货溢价**紧急采购，直接抬高单机成本。
5. **建园区**：6 块地块，6 类楼宇（总部/研发/生产/设计/物流/品质），施工按工期倒计时，建成后提供产能、研发速度、渠道成本等加成，并可继续升级。
6. **定价与渠道**：每个市场单独定价，需求由产品力、品牌、价格弹性与渠道覆盖共同决定；`¥80 万`进入一个新市场，`¥500 万`办发布会制造三个月热度。
7. **选产品线**：新机型分旗舰 / 数字 / 青春 / 商务 / 游戏五条线，定价倍数与人群吸引力各不相同。
8. **带团队**：招聘/加薪/解雇/调部门之外，还能送员工参加 4 类培训；能力决定职级（初级→专家），并可任命部门主管与高管。
9. **发布会与拆解**：办发布会时进入 3D 舞台（追光、观众、巨型背景屏）；设计器可切「拆解视图」逐层展开内部结构。
10. **经营与研发**：立项研发科技，控制营销预算，处理随机事件与自动借款。
11. **资本运作**：多轮股权融资、IPO 上市、收购陷入困境的竞品机型。
12. **七个里程碑**：首款上市 → 10 万台 → 全球 1% → 自建工厂 → 5 个市场 → 年营收 10 亿 → 全球 5%。

## 已实现的系统

| 模块 | 说明 |
| --- | --- |
| 科技树 | 5 大类 60+ 节点，按年代与前置依赖解锁，研发进度由人数、预算、国家科研水平决定 |
| 3D 设计器 | 参数化建模：机身挤出圆角、屏幕贴图（状态栏/图标/Dock）、摄像头模组与镜圈、侧键、logo、折叠铰链；轨道相机四视角预设 |
| 拆解视图 | 一键把机身、屏幕、玻璃、主板、电池、听筒、马达、排线、后盖、摄像头沿 Z 轴分层展开，配镜头动画与 HTML 图例 |
| 2D 六视图 | 正视/后视/左视/右视/顶视/底视，统一比例尺，标注尺寸 |
| 园区建造 | 6 地块 / 6 类楼宇 / 最高 5 级；工期倒计时、升级工期 70%、加成聚合进产能·研发·设计·渠道·售后·品牌·工位 |
| 供应链 | 芯片·显示·存储·摄像头·电池·结构件，交期 1–3 个月，受供应链人力缩短；在途订单、库存覆盖、周转天数、缺料现货溢价 16% |
| 员工成长 | 5 级职级（能力阈值 0/56/68/80/90，薪资系数 1.0–1.72）+ 4 个培训项目（按月扣费、结业加成、可中途停训） |
| 发布会舞台 | three.js 舞台：圆形台面、抠像背景屏、双追光、观众闪光灯、机型悬浮，开场镜头推近 |
| 市场模拟 | 12 个市场，各自人口、消费力、关税与偏好权重；效用函数 = 性能/影像/续航/设计/品牌 − 价格弹性 |
| 消费者分群 | 7 类人群（低预算/普通/商务/游戏/摄影/科技/高端），每个市场有自己的人群体量结构；份额按人群分别计算再加权 |
| 产品线 | 旗舰 / 数字 / 青春 / 商务 / 游戏，各有定价定位与人群吸引力系数，销量按人群倾向分流 |
| 产品评价 | 用户评分、媒体评测、故障率、退货率；故障与退货产生真实现金支出，口碑经 `wordOfMouth()` 回灌品牌与下一代 |
| 组织架构 | 9 个部门 + CEO/高管席位，可任命主管并给部门加成；部门「工作重点」滑块影响成本/质量结算 |
| 资本运作 | 3–6 轮股权融资（出让比例按投前估值算）、IPO 四项门槛、并购竞品陷入困境的机型 |
| 竞品 AI | 9 家厂商，按品牌调性研发、发布新机、定价，机型会老化退市 |
| 财务 | 收入/COGS/渠道分成/售后/退货/工资/租金/营销/研发/培训/利息/税，现金流与损益两条线分开 |
| 年代基准 | 用「该年代全部可得科技」造一台主流机当锚点，评分与建议定价都按同代倍率换算（见下） |
| 里程碑 | 七个阶段目标，达成写入日志并加品牌 |
| 存档 | 3 个槽位 + 自动存档，key 随版本号走（v5），旧 v4/v3 存档自动回退读取并迁移补齐新字段 |

### 年代基准与经济校准

从 1980 玩到 2035，绝对分值会失效：1980 年的顶级手机性能只有 2 分，拿固定的 50 分做参照会判成垃圾；2020 年的主流机性能 84 分，同一把尺子又全员优秀。

- `eraBaseline(year)`：用该年代全部可得科技造一台主流机，它是那个年代的「50 分」。
- `eraRel(value, base)`：把任意指标换算成同代倍率，1.0 = 与主流机持平，1.5 = 明显更强。
- `eraCostScale(year)`：把主流机 BOM 锚定到零售价的 52%，让 1980 的 63 倍加价与 2020 的 0.7 倍加价统一成 1.92 倍。

没有这三条，早期年代是印钞机、晚期年代卖一台亏一台；现在是同一条难度曲线。

## 与 GDD 的差距

- 园区 3D：建造系统已完整接入结算，但园区 3D 场景仍只渲染总部办公室，尚未把地块与楼宇实体画进场景。
- 供应链：只有采购与交期，没有多供应商比价、长期合同与断供事件。
- 房间级建造：只到「买地 + 盖楼」，没有 GDD 第十一章的墙壁、门窗、家具与设备摆放。
- 3D 员工：在场人物是静态模型，没有寻路、上班/休息行为与随机外观。
- 双视角：只有轨道旋转与缩放，没有 45° 等距 ↔ 正俯视切换、平移与镜头跟随。
- 政策系统：GDD 第十五章列了 12 类政策，目前只有一条「产业补贴」随机事件。
- 生产线：没有工艺差异、自动化程度与自研设备。
- 音效：全项目 0 个音频文件。
- 3D 渲染：有发布会舞台与拆解运镜，没有机身配色/材质的分层渲染。
